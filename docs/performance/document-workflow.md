# 文稿流程性能记录

本记录对应 `perf/file-io-and-input` 上的文稿读写与输入处理改动。基线提交是 `4631ce51fcb2000f42b1d730aa41bc5aaa237269`。

## 本次没有设备采样

没有在手机或模拟器上采集 Trace，也没有记录打开、保存、草稿、输入到下一帧、分析、JSON 或 Web 更新的耗时。因此这里不写中位值、最慢值、内存或前后对比。Node 测试耗时不能代替这些数字。

任务 6 的触发条件是：代表性样本的编码、解码、JSON、大纲或查找计数超过 16 ms，或在主线程上重复成为长任务。16 ms 只用于决定要不要迁出计算，不是平台保证。本次没有这项测量，所以没有把编码、摘要、大纲或查找移到 TaskPool。这些计算仍在调用它们的界面线程上执行。

## 已完成的结构变化

- 打开、保存、删除前读取、草稿和分享副本使用异步文件接口。编码、容量检查、SHA-256 和写后校验仍在调用线程完成。
- 草稿由单一协调器串行写入。停笔 450 ms 提交，调度最长等待 2 s；落盘完成时间取决于存储。失败重试会在随后的新编辑、清理或换篇之后作废。这项由单元测试覆盖，没有设备耗时。
- Markdown 大纲和查找计数按需合并。没有打开大纲或查找时不扫描全文。
- 预览按是否可见工作。关闭时不发送更新。LaTeX 只看大纲时不生成完整页面。每个 Web 实例最多一笔在途发送和一笔最新请求。
